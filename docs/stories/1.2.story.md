### Architecture Context

**Database Schema** [Source: docs/architecture/database-schema.md]:

Complete schema details for all 7 tables (see epic for full details):
- competitions, stages, measures, competitors, competition_competitor, attempts, attempt_results
- Migration order matters due to foreign key dependencies
- Cascade deletes configured: deleting competition deletes all related data

**Nullable Fields** [Source: docs/architecture/database-schema.md#required-vs-nullable-fields-summary]:
Only these fields may be NULL:
- `competitor.bar_name`
- `competitor.instagram`
- `competitor.diffords_profile`
- `attempt.started_at`
- `attempt.ended_at`
- `attempt.duration_ms`
- `stage.name`

**Business Rules** [Source: docs/architecture/database-schema.md]:
- ONE attempt per competitor per stage (no retries)
- Competitors complete stages in series (not parallel)
- Cascade delete: deleting competition removes all stages, measures, attempts, results
- Stages can be reordered after creation

**Coding Standards** [Source: docs/architecture/coding-standards.md]:
- Use `declare(strict_types=1);` at top of all PHP files
- Follow Laravel naming conventions:
  - Models: Singular PascalCase (Competition, Stage, etc.)
  - Tables: Plural snake_case (competitions, stages, etc.)
  - FKs: `{table_singular}_id` (competition_id, stage_id, etc.)
- Use fillable arrays (not guarded)
- Type hint all methods
- Add PHPDoc blocks for clarity

### Migration Details

**Migration Order** [Source: docs/architecture/database-schema.md#migration-order]:
Must be created and run in this order:
1. competitions
2. stages (requires competitions)
3. measures (requires stages)
4. competitors
5. competition_competitor (requires competitions and competitors)
6. attempts (requires competitions, competitors, stages)
7. attempt_results (requires attempts and measures)

**Enum Values**:
- competition.status: `draft`, `active`, `completed` (default: `draft`)
- stage.status: `pending`, `active`, `complete` (default: `pending`)

**Foreign Keys with Cascade**:
All foreign keys should use `->onDelete('cascade')` to enforce data integrity.
