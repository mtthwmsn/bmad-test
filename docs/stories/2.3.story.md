# Story 2.3: Stage & Measure Management (Inline)

## Status: Done

## Story

- As a **referee**
- I want **to manage stages and measures directly within the competition edit view**
- so that **I can define the structure of pour tests without navigating to separate screens**

## Acceptance Criteria (ACs)

1. Competition edit view shows all existing stages
2. Can add new stage with order, name, expected_seconds, status
3. Can edit stage details inline
4. Can delete stage (with confirmation if has measures)
5. Each stage shows its measures
6. Can add/edit/delete measures per stage
7. Reordering stages updates `order` field
8. All changes persist to database
9. Validation prevents invalid data (e.g., negative ml values, negative seconds)

### Architecture Context

**StageController** [Source: docs/architecture/backend-architecture.md]:

Routes:
- `POST /admin/competitions/{competition}/stages` → `store()` - Create stage
- `PUT /admin/stages/{stage}` → `update()` - Update stage
- `DELETE /admin/stages/{stage}` → `destroy()` - Delete stage

**MeasureController** [Source: docs/architecture/backend-architecture.md]:

Routes:
- `POST /admin/stages/{stage}/measures` → `store()` - Create measure
- `PUT /admin/measures/{measure}` → `update()` - Update measure
- `DELETE /admin/measures/{measure}` → `destroy()` - Delete measure

**Stage Validation Rules**:
- `order`: required, integer, min:1
- `name`: nullable, string, max:255
- `expected_seconds`: required, integer, min:1
- `status`: required, in:draft,active,completed

**Measure Validation Rules**:
- `name`: required, string, max:255
- `target_ml`: required, numeric, min:0.1
- `order`: required, integer, min:1

**Coding Standards** [Source: docs/architecture/coding-standards.md]:
- Use `declare(strict_types=1);` at top of all PHP files
- Type hint all methods
- Use Form Request classes for validation
- Keep controllers thin

### Implementation Details

**Controller Structure (StageController)**:
```php
class StageController extends Controller
{
    public function store(StoreStageRequest $request, Competition $competition): RedirectResponse
    {
        $competition->stages()->create($request->validated());
        return redirect()->route('admin.competitions.edit', $competition)
            ->with('success', 'Stage added successfully.');
    }

    public function update(UpdateStageRequest $request, Stage $stage): RedirectResponse
    {
        $stage->update($request->validated());
        return redirect()->route('admin.competitions.edit', $stage->competition)
            ->with('success', 'Stage updated successfully.');
    }

    public function destroy(Stage $stage): RedirectResponse
    {
        $competition = $stage->competition;
        $stage->delete(); // Cascade deletes measures
        return redirect()->route('admin.competitions.edit', $competition)
            ->with('success', 'Stage deleted successfully.');
    }
}
```

**Controller Structure (MeasureController)**:
```php
class MeasureController extends Controller
{
    public function store(StoreMeasureRequest $request, Stage $stage): RedirectResponse
    {
        $stage->measures()->create($request->validated());
        return redirect()->route('admin.competitions.edit', $stage->competition)
            ->with('success', 'Measure added successfully.');
    }

    public function update(UpdateMeasureRequest $request, Measure $measure): RedirectResponse
    {
        $measure->update($request->validated());
        return redirect()->route('admin.competitions.edit', $measure->stage->competition)
            ->with('success', 'Measure updated successfully.');
    }

    public function destroy(Measure $measure): RedirectResponse
    {
        $competition = $measure->stage->competition;
        $measure->delete();
        return redirect()->route('admin.competitions.edit', $competition)
            ->with('success', 'Measure deleted successfully.');
    }
}
```

**UI Design Approach**:
- Stages displayed as accordion/collapsible cards
- Each stage card shows: order badge, name, expected_seconds, status badge
- Measures displayed as nested list within each stage card
- Add/Edit forms can be inline or in modals (inline preferred for simplicity)
- Delete buttons use JavaScript confirmation
- Use Alpine.js or vanilla JS for interactivity (no Livewire for now)
